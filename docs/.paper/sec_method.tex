\section{Problem Formulation \& Methodology}
\label{sec:method}

In this section, we formally define the repository-scale code translation problem, describe the overall architecture of MAgHARCM, and detail the four cooperating agents comprising our pipeline.

\subsection{Problem Formulation}
\label{sec:method_formulation}

We formalize repository-scale translation as a structured mapping between source and target software projects. A source software project is defined as a tuple:
\begin{equation}
P_s = (F_s, T_s, D_s, \mathcal{M}_s)
\end{equation}
where $F_s = \{f_1, f_2, \dots, f_n\}$ is the set of source code files written in source language $L_s$, $T_s = \{t_1, t_2, \dots, t_m\}$ is the associated suite of test files, $D_s$ represents the external third-party library dependencies declared in the project build manifest, and $\mathcal{M}_s$ denotes the directory and module structure.

The objective of repository translation is to synthesize a corresponding target project:
\begin{equation}
P_t = (F_t, T_t, D_t, \mathcal{M}_t)
\end{equation}
in target language $L_t$ (such as Rust) such that the following three formal correctness properties are simultaneously satisfied:
\begin{enumerate}
    \item \textbf{Syntactic and Type Compilation Validity ($\mathcal{C}$):} The target project $P_t$ compiles cleanly under the standard target compiler toolchain $\mathcal{T}_{L_t}$ without compilation errors:
    \begin{equation}
    \mathcal{C}(P_t) = \text{Compile}(\mathcal{T}_{L_t}, P_t) = \text{True}
    \end{equation}
    \item \textbf{Observational Semantic Equivalence ($\mathcal{E}$):} For every source function $u_s \in F_s$ and its corresponding translated target function $u_t \in F_t$, their execution outputs must be identical across all valid input domains $I$:
    \begin{equation}
    \forall x \in I, \quad \text{Exec}(u_s, x) \equiv \text{Exec}(u_t, x)
    \end{equation}
    \item \textbf{Test Suite Verification \& Assertion Integrity ($\mathcal{V}$):} The translated test suite $T_t$ must execute cleanly, passing all assertions, while strictly preserving or expanding the assertion coverage of the original test suite $T_s$:
    \begin{equation}
    \begin{aligned}
    \mathcal{V}(T_t, P_t) = &\left( \text{TestPassRate}(T_t) = 1.0 \right) \ \land \\
    &\left( \text{AssertCount}(T_t) \ge \text{AssertCount}(T_s) \right)
    \end{aligned}
    \end{equation}
\end{enumerate}

\subsection{System Architecture Overview}
\label{sec:method_arch}
\begin{algorithm}[MAgHARCM Repository Translation Orchestration]
\label{alg:magharcm_pipeline}
\begin{algorithmic}[1]
\Require Source project $P_s$, Source language $L_s$, Target language $L_t$, Max iterations $K$
\Ensure Translated target project $P_t$
\State $G_{\text{AST}}, \text{Manifest} \gets \Call{ExtractAST}{P_s}$
\State $\mathcal{S}_{\text{strat}}, \text{Design} \gets \Call{Analyze}{G_{\text{AST}}, \text{Manifest}, L_s, L_t}$
\State $DAG, \text{Plan}, \text{Skel} \gets \Call{Plan}{G_{\text{AST}}, \text{Design}, L_s, L_t}$
\State $P_t \gets \Call{InitializeCrate}{\text{Skel}, \text{Plan}}$
\State $P_t \gets \Call{TranslateChunked}{\text{Translator}, P_t, \text{Plan}}$
\State $\text{SaveCheckpoint}(P_t, \text{iter}=0)$
\State $\text{iter} \gets 0$
\While{$\text{iter} < K$}
    \State $\text{Report} \gets \text{ValidatorAgent}.\text{Validate}(P_t, P_s)$
    \If{$\text{Report}.\text{AllSuccess} = \text{True}$}
        \State \Return $P_t$ \Comment{Successfully converged}
    \EndIf
    \If{$\text{Report}.\text{PlateauDetected} \lor \text{Report}.\text{Weakened}$}
        \State \textbf{break} \Comment{Coverage plateau or security guard triggered}
    \EndIf
    \State $P_t \gets \text{TranslatorAgent}.\text{Repair}(P_t, \text{Report})$
    \State $\text{iter} \gets \text{iter} + 1$
    \State $\text{SaveCheckpoint}(P_t, \text{iter})$
\EndWhile
\State \Return $P_t$
\end{algorithmic}
\end{algorithm}

\subsection{Analyzer Agent \& M\"uller Strategy Selection}
\label{sec:method_analyzer}

The Analyzer Agent inspects the incoming codebase $P_s$ to construct a structured architectural specification. Using Tree-Sitter grammars for C, Go, and Java, the agent parses the full directory hierarchy, identifying module boundaries, public struct declarations, function signatures, and build configurations.

To tailor downstream decomposition to the repository's scale, the Analyzer implements \emph{M\"uller Migration Strategy Selection}~\cite{muller2022towards}, categorizing projects into three distinct regimes:
\begin{itemize}
    \item \textbf{Direct Strategy ($\le 5$ files and $\le 1{,}000$ LoC):} Applied to compact utility packages. Translation proceeds in a single unified prompt containing all module definitions.
    \item \textbf{Incremental Strategy ($5 < |F_s| \le 50$ files or $1{,}000 < \text{LoC} \le 10{,}000$):} Standard multi-module repositories. The codebase is translated module-by-module in reverse-topological order.
    \item \textbf{Pilot Strategy ($> 50$ files or $> 10{,}000$ LoC):} Large-scale enterprise codebases (e.g., Apache Commons). The Analyzer selects a core foundational subsystem as a self-contained pilot before expanding to peripheral packages.
\end{itemize}

\subsection{Planning Agent \& Reverse-Topological DAG}
\label{sec:method_planning}

The Planning Agent converts the architectural analysis into an executable dependency schedule. A critical failure mode in multi-file translation is caller-before-callee synthesis: if module $A$ depends on types declared in module $B$, translating $A$ first causes the LLM to invent placeholder type signatures for $B$, resulting in pervasive type mismatches when $B$ is subsequently translated.

To guarantee that dependencies are resolved prior to usage, the Planning Agent constructs a fine-grained call graph $G = (V, E)$ over all extracted AST fragments. We then compute a \emph{Reverse-Topological Order} using depth-first search (DFS) with cycle elimination, formalized in Algorithm~\ref{alg:reverse_topo}.
\begin{algorithm}[Cycle-Free Reverse-Topological Scheduling]
\label{alg:reverse_topo}
\begin{algorithmic}[1]
\Ensure Reverse-topological execution sequence $\mathcal{Q}$
\State $\text{Visited} \gets \emptyset, \quad \text{OnStack} \gets \emptyset, \quad \mathcal{Q} \gets []$
\Function{Visit}{$u$}
    \State $\text{Visited} \gets \text{Visited} \cup \{u\}$
    \State $\text{OnStack} \gets \text{OnStack} \cup \{u\}$
    \For{$(u, v) \in E$}
        \If{$v \in \text{OnStack}$}
            \State $E \gets E \setminus \{(u, v)\}$ \Comment{Cut cyclic back-edge}
        \ElsIf{$v \notin \text{Visited}$}
            \State \Call{Visit}{$v$}
        \EndIf
    \EndFor
    \State $\text{OnStack} \gets \text{OnStack} \setminus \{u\}$
    \State $\mathcal{Q}.\text{append}(u)$
\EndFunction
\For{$u \in V$}
    \If{$u \notin \text{Visited}$}
        \State \Call{Visit}{$u$}
    \EndIf
\EndFor
\State \Return $\mathcal{Q}$
\end{algorithmic}
\end{algorithm}

When circular dependencies are detected (i.e., node $v$ is on the active DFS recursion stack), the back-edge $(u, v)$ is removed from the planning DAG and recorded in the repair ledger. Furthermore, the Planning Agent includes a \emph{Canonical Manifest Rewriter} that deterministically maps source library identifiers (e.g., Java `org.apache.commons.validator` or Go `math/rand`) to standard Rust equivalents (`validator`, `rand`, `regex`) in the target `Cargo.toml`.

\subsection{Translator Agent \& Bounded Context Synthesis}
\label{sec:method_translator}

The Translator Agent implements chunked code synthesis using our dedicated coding model (Qwen3-4B-Instruct) guided by the high-level topological plan emitted by the reasoning model (Qwen3-30B-Thinking). Because local models operate under bounded context budgets, providing full repository source histories causes catastrophic attention degradation.

As shown in Figure~\ref{fig:dataflow}, MAgHARCM employs a two-tier context bounding mechanism:
\begin{enumerate}
    \item \textbf{Symbol-Aware Navigator:} When synthesizing module fragment $u_k$, the Navigator extracts only the structural definitions, struct layouts, and public function signatures of its immediate callees, capping the extracted slice to $\le 4$\,KB.
    \item \textbf{Prior-Modules Memory:} For previously translated modules, the Translator maintains an in-memory digest of emitted Rust signatures, bounded by a 4\,KB total budget with 200-byte head/tail snippets.
\end{enumerate}

\subsection{Validator Agent \& Adversarial Defense}
\label{sec:method_validator}

\begin{figure}[t]
    \centering
    \includegraphics[width=\columnwidth]{figures/fig4_lifecycle.png}
    \caption{Translation Lifecycle State Machine. Highlights the forward translation rail, state checkpoint persistence, coverage plateau stall detection, and adversarial test-weakening guard exits.}
    \label{fig:lifecycle}
\end{figure}

The Validator Agent enforces strict verification over the synthesized codebase through a five-stage validation cascade:
\begin{enumerate}
    \item \textbf{Pre-Compilation AST Syntax Validation:} Fast AST verification via Tree-Sitter to detect unclosed delimiters, invalid keywords, or malformed macro expansions prior to invoking compiler toolchains.
    \item \textbf{Target Toolchain Build Compilation:} Executes \texttt{cargo check} and \texttt{cargo build} in the target workspace, capturing structured diagnostic errors ($E0382, E0502, E0432$).
    \item \textbf{Test Suite Execution:} Runs native target unit tests (\texttt{cargo test}), computing passed, failed, and total test counts.
    \item \textbf{Adversarial Weakening Guard:} LLM-driven repair loops frequently delete failing assertions or convert strict equality checks into no-ops (e.g., \texttt{assert\_eq!(a, b)} $\to$ \texttt{assert!(true)}). The Validator parses AST assertion counts across test files: if $\text{AssertCount}(T_t^{\text{new}}) < \text{AssertCount}(T_t^{\text{prev}})$, the update is flagged as an adversarial weakening regression, rejected, and reverted to the last green snapshot.
    \item \textbf{CodaMOSA-derived Coverage Plateau Detector:} To prevent endless repair loops on unresolvable semantic bugs, the Validator tracks test coverage deltas across iterations. If two consecutive iterations yield a passed-tests delta $< 5$ and an uncovered-function delta $< 1$, execution is gracefully halted at a convergence plateau.
\end{enumerate}
