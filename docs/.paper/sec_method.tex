\section{Methodology}
\label{sec:method}

MAgHARCM is implemented in Go on top of CloudWeGo Eino's cyclic graph
runtime. While inheriting the core multi-agent paradigm of ReCodeAgent
\citep{ibrahimzada2025recodeagent}, MAgHARCM formalizes a 6-stage
neuro-symbolic pipeline grounded in 26 evidence-backed primitives
(Appendix~\ref{app:primitives}) and specifically engineered to execute
against local Small Language Models (SLMs) through Ollama.

\subsection{The 6-Stage Translation Pipeline}

The architecture structures the migration lifecycle into six sequential and
cyclic stages:

\begin{enumerate}
\item \textbf{Stage 1: Intake.} Ingests the source codebase path, target language,
and target framework. Using \texttt{internal/tools/pa.go} backed by Tree-sitter
parsers across supported grammars, Intake extracts the complete repository
manifest, file hierarchy, and language AST element inventory.

\item \textbf{Stage 2: Analyze (Analyzer Agent).} Emits a comprehensive
\emph{Source Project Research} document. Driven by a local reasoning model
(\texttt{lfm2.5:8b-a1b-q4\_K\_M} MoE), the Analyzer assigns architectural
concepts, extracts dependency mappings, and executes \emph{M\"uller Strategy Selection}
(NEW-PRIM-21) to classify the codebase into one of five migration strategies
(\texttt{BIG\_BANG}, \texttt{INCREMENTAL}, \texttt{PILOT}, \texttt{FROZEN\_LEGACY},
or \texttt{PARALLEL\_CUTOVER}).

\item \textbf{Stage 3: Plan (Planning Agent).} Decomposes the high-level design
into granular translation units. It generates symbol name mappings, constructs
the compilable target skeleton files (e.g. \texttt{Cargo.toml}, \texttt{src/lib.rs}),
invokes the \emph{Manifest Rewriter} (NEW-PRIM-31) to map third-party dependencies to
canonical target crates, and computes a \emph{Reverse-Topological Order} with
\emph{Back-Edge Removal} (NEW-PRIM-1, NEW-PRIM-2) over the call/dependency graph to
ensure callees and dependencies are scheduled before callers.

\item \textbf{Stage 4: Translate (Translator Agent \& Navigator).} Operates
either in single-shot mode (for small repos) or via the \emph{Chunked Translator}
(NEW-PRIM-23). The chunked dispatcher groups fragments by topological source-file
order, issue-scoped to $\sim 500$-LoC or function-cluster boundaries. Each step
queries the \emph{Symbol-Aware Navigator} (NEW-PRIM-26) for precise $\le 4$\,KB
context slices (definition, references, type signature) and injects a compact
running summary of previously emitted modules to ensure cross-module symbol coherence.

\item \textbf{Stage 5: Validate (Validator Agent).} Executes a multi-stage
validation cascade (NEW-PRIM-6): (i)~pre-compilation AST syntax verification (GAP-08);
(ii)~target toolchain compilation (\texttt{cargo check}); (iii)~test suite execution
(\texttt{cargo test}); and (iv)~the \emph{Adversarial Weakening Guard} (NEW-PRIM-13),
which compares assertion counts and test body lengths against prior iterations to
prevent vacuous test relaxation.

\item \textbf{Stage 6: Repair Loop (Bounded Cyclic Graph).} If compilation or test
failures are detected, the error diagnostics and failing assertions are fed back to
the Translator in repair mode. The repair loop is bounded (default 10 iterations) and
features \emph{Plateau-Bounded Test Remediation} (NEW-PRIM-27) derived from CodaMOSA
and \emph{Conversable Checkpointing} (NEW-PRIM-28) to persist state snapshots under
\texttt{.artifacts/<run-id>/checkpoints/} after every iteration.
\end{enumerate}

\begin{algorithm}[t]
\caption{MAgHARCM 6-Stage Translation and Repair Loop}
\label{alg:magharcm_pipeline}
\begin{algorithmic}[1]
\Require Source repo $P_s$, Target lang $L_t$, Max iterations $K$, Timeout $T$
\Ensure Translated and validated target project $P_t$
\State $\mathcal{M}_s \gets \Call{Intake}{P_s}$ \Comment{Stage 1: Manifest \& ASTs}
\State $\mathcal{R}, \mathcal{S} \gets \Call{Analyze}{\mathcal{M}_s, L_t}$ \Comment{Stage 2: Research \& Strategy}
\State $\mathcal{F}, \mathcal{K}, \mathcal{O}_{topo} \gets \Call{Plan}{\mathcal{M}_s, \mathcal{R}}$ \Comment{Stage 3: Skeleton \& Reverse Topo}
\State $P_t \gets \mathcal{K}$ \Comment{Initialize target with skeleton}
\State $P_t \gets \Call{TranslateChunked}{\mathcal{F}, \mathcal{O}_{topo}, P_t}$ \Comment{Stage 4: Chunked Translation}
\For{$iter \gets 1 \textrm{ to } K$}
  \State $\mathcal{V} \gets \Call{Validate}{P_t}$ \Comment{Stage 5: Multi-stage validate}
  \If{$\mathcal{V}.all\_success$}
    \State \textbf{break}
  \EndIf
  \State $\Call{CheckpointState}{P_t, \mathcal{V}, iter}$ \Comment{Conversable checkpoint}
  \State $P_t \gets \Call{RepairTranslator}{P_t, \mathcal{V}}$ \Comment{Stage 6: Targeted repair}
  \If{$\Call{DetectWeakening}{\mathcal{V}}$}
    \State $\Call{LogWarning}{\text{Adversarial test weakening detected}}$
  \EndIf
\EndFor
\State \Return $P_t$
\end{algorithmic}
\end{algorithm}

\subsection{Chunked Translation with Running Context (NEW-PRIM-23)}

Single-shot translation fails catastrophically on non-trivial repositories because
monolithic prompts exceed the effective instruction-following context of small coding
models (e.g. 4B parameters), leading to empty tool calls or truncated files.
NEW-PRIM-23 overcomes this by decomposing the translation into topologically ordered
chunks:

\begin{algorithm}[t]
\caption{Chunked Translation Dispatch (NEW-PRIM-23)}
\label{alg:chunked}
\begin{algorithmic}[1]
\Require Fragments $\mathcal{F}$, Topological Order $\mathcal{O}$, Target Skeleton $\mathcal{K}$
\Ensure Translated Files map $\mathcal{T}$
\State $\mathcal{T} \gets \mathcal{K}$
\State $\mathcal{G} \gets \Call{GroupBySourceFile}{\mathcal{F}, \mathcal{O}}$
\For{each source group $g \in \mathcal{G}$}
  \State $\mathcal{C}_{prior} \gets \Call{BuildPriorModulesSummary}{\mathcal{T}, \text{budget}=4\text{KB}}$
  \State $\mathcal{S}_{nav} \gets \Call{NavigatorLookupSymbols}{g.symbols}$
  \State $\mathcal{P} \gets \Call{RenderChunkPrompt}{g, \mathcal{C}_{prior}, \mathcal{S}_{nav}}$
  \State $\mathcal{T}_{new} \gets \Call{CodingModelGenerate}{\mathcal{P}}$
  \State $\mathcal{T} \gets \mathcal{T} \cup \mathcal{T}_{new}$
  \State $\Call{SyncToDisk}{\mathcal{T}}$
\EndFor
\State \Call{EnsureTargetManifest}{\mathcal{T}} \Comment{Ensure Cargo.toml / go.mod present}
\State \Return $\mathcal{T}$
\end{algorithmic}
\end{algorithm}

\noindent
As shown in Algorithm~\ref{alg:chunked}, each chunk prompt is furnished with:
(1)~the current source fragment; (2)~a bounded 4\,KB summary of prior emitted
module signatures and public types (\texttt{BuildPriorModulesSummary}); and
(3)~symbol definitions from the Navigator. This gives the local coding model
the exact context required to emit valid cross-file references without blowing up
its context window.
