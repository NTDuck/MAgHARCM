\section{Related Work}
\label{sec:related}

Repository-scale code translation has been studied across rule-based transpilers, neuro-symbolic pipelines, and LLM-based agentic systems. We group prior work along four axes that map to the four challenges in \S\ref{sec:intro_challenges}.

\subsection{Rule-Based Transpilation and AST Rewriting}
\label{sec:related_transpilers}

Rule-based transpilers perform deterministic AST rewrites from a source grammar to a target grammar. \textsc{C2Rust}~\cite{c2rust,p38_c2rust} is the canonical C-to-Rust transpiler: it preserves C memory layouts and emits Rust code with explicit \texttt{unsafe} blocks and raw pointer operations. The tool requires $\ge 100\,\text{K}$~LoC of rewrites per source--target pair and produces unidiomatic output that demands human refactoring before it can satisfy Rust's safety guarantees~\cite{siddiq2024oxidizer,p05_oxidizer,p50_rav1d_c2rust_case,p51_libexpat_c2rust_case}. Other rule-based systems target narrower pairs: \textsc{CxGo} for C-to-Go, \textsc{Sharpen} for Java-to-C\#, and \textsc{JavaToCSharp}. General-purpose AST rewriters like \textsc{OpenRewrite}~\cite{p39_openrewrite} encode migration recipes as composable visitors but cannot bridge type-system divergences that arise between systems languages.

\subsection{Neuro-Symbolic Repository Translation}
\label{sec:related_neurosym}

Neuro-symbolic systems replace hand-written rewrite rules with LLM synthesis guided by program-analysis infrastructure.

\textsc{AlphaTrans}~\cite{yang2024alphatrans,p02_alphatrans} is the most extensively evaluated neuro-symbolic system. It combines static type analysis, a deterministic translation pipeline, and GraalVM-based test translation. The approach is engineered for the Java-to-Python pair and does not generalise to new language pairs without re-implementing the analysis infrastructure. The authors report that long call chains in test suites produce a \emph{test translation coupling effect}: a buggy callee blocks the validation of every downstream test, motivating ReCodeAgent's separation of test execution and test generation~\cite{p01_recodeagent,p02_alphatrans}.

\textsc{Oxidizer}~\cite{siddiq2024oxidizer,p05_oxidizer} targets Go-to-Rust through type-driven synthesis and language-feature mapping. The system extracts input/output pairs by executing source tests and generates mock tests in the target language for validation. Oxidizer demonstrates that test coverage is a useful proxy for translation correctness but does not address the absence of an executable test suite in many real-world projects.

\textsc{Skel}~\cite{p64_skel,p65_skel_pldi} generates target-language skeletons (compilable frameworks with declarations but no implementations) and uses execution traces from the source language to drive translation. Skel shows that skeleton generation reduces hallucinated type signatures and supports incremental translation, a primitive MAgHARCM also adopts. Skel was evaluated primarily on the Python-to-JavaScript pair.

\textsc{Syzygy}~\cite{p58_syzygy,p51_syzygy_arxiv} is a dual code-test C-to-(safe)-Rust translator that combines LLM synthesis with dynamic analysis on hardware-in-the-loop test execution. Syzygy's bidirectional validation prevents some translation regressions but couples tightly to a single source--target pair.

\textsc{VERT}~\cite{p72_vert} is a polyglot verified equivalent Rust transpiler that proves translation equivalence through symbolic reasoning. The system demonstrates high assurance for narrow problem domains but does not generalise to multi-file repositories.

\subsection{Agentic Repository Translation}
\label{sec:related_agents}

Recent agentic systems coordinate one or more LLM agents over reasoning-action-observation loops~\cite{yao2023react}.

\textsc{ReCodeAgent}~\cite{ibrahimzada2026recodeagent,p01_recodeagent} is the closest prior work. It coordinates four specialised agents (Analyzer, Planning, Translator, Validator) through an explicit \textsc{Analyze} $\to$ \textsc{Plan} $\to$ \textsc{Translate} $\to$ \textsc{Validate} $\to$ \textsc{Repair} loop, exposes a Model-Context-Protocol tool surface combining LSP queries and Tree-sitter-based project-analysis tools, and translates developer-written tests within the same Translator Agent rather than treating tests as a separate concern. ReCodeAgent is engineered to run on Anthropic Claude Sonnet through Claude Code, is evaluated on 118 projects spanning four language pairs and six languages, and reports a 99.4\% compilation success rate and an 86.5\% test pass rate on validated developer tests. MAgHARCM adopts the same four-agent decomposition and explicit orchestration algorithm but targets local quantized SLMs and currently restricts its target language to Rust.

\textsc{Crust-Bench / SWE-agent}~\cite{p30_crust_bench,yang2024sweagent,yang2024sweagent_neurips} adapts the SWE-agent~\cite{yang2024sweagent} harness to C-to-Rust translation. The agent relies on basic file-navigation and build/test commands and is compared against a generate-then-repair loop; on the Crust benchmark SWE-agent under-performs the generate-repair loop on test pass rate while wasting many turns on file navigation. Crust's evaluation compares 100 independent C projects translated to Rust with validated test suites.

\textsc{ACToR}~\cite{p31_actor} is an adversarial agent-collaboration system for C-to-Rust translation that relies on CLI differential fuzzing. The approach is limited to programs with CLI front-ends and is not directly comparable to MAgHARCM on repository benchmarks without command-line interfaces.

\textsc{RepoTransAgent}~\cite{p62_repograph,p52_repotransagent} is a multi-agent LLM framework for repository-aware code translation. The system relies on hard-coded Java-to-C\# lookup tools and does not generalise beyond that source--target pair.

\textsc{MatchFixAgent}~\cite{p08_matchfixagent} focuses on autonomous validation and repair for repository-level translation; it is complementary to MAgHARCM's repair loop.

General-purpose multi-agent software-engineering frameworks such as \textsc{MetaGPT}~\cite{hong2023metagpt,p11_metagpt}, \textsc{ChatDev}~\cite{qian2023chatdev,p12_chatdev}, \textsc{HyperAgent}~\cite{p13_hyperagent,p47_hyperagent_deepread}, \textsc{AgentVerse}~\cite{p26_agentverse}, and \textsc{AutoGen}~\cite{p16_autogen,p48_autogen_deepread} coordinate agents across discrete development roles (product manager, architect, developer, QA) but do not embed the program-analysis primitives required for repository-scale translation.

\subsection{Retrieval-Augmented and Context-Bounded Generation}
\label{sec:related_retrieval}

A complementary line of work augments LLM translation with retrieval and structured context. \textsc{CodePlan}~\cite{p03_codeplan}, \textsc{RepoCoder}~\cite{p61_repocoder}, and \textsc{RepoGraph}~\cite{p62_repograph} leverage structured dependency graphs to supply precise context slices. \textsc{RustMap}~\cite{p05_rustmap} uses program-analysis and LLM collaboration for project-scale C-to-Rust migration. \textsc{EvoC2Rust}~\cite{p66_evoc2rust} applies a skeleton-guided framework at the project level; \textsc{C2SaferRust}~\cite{p43_c2saferrust} integrates neuro-symbolic techniques to produce safer Rust. \textsc{SACTOR}~\cite{p81_sactor} combines LLM-driven synthesis with FFI-based verification. \textsc{Pointer Knowledge Graphs}~\cite{p79_pkg} capture pointer semantics to drive project-level C-to-Rust translation.

The bounded-context primitive used by MAgHARCM ($\le 4$\,KB Symbol Navigator and $\le 4$\,KB Prior-Modules Memory) is most directly inspired by the dynamic context-folding strategies used in long-horizon agent literature~\cite{p53_context_folding,p06_long_horizon} and by the $\le 4$\,KB symbol-navigator budget adopted by \textsc{HyperAgent}~\cite{p13_hyperagent,p47_hyperagent_deepread}.

\subsection{Local-SLM Code Generation}
\label{sec:related_local}

A growing body of work targets local Small Language Models for code tasks~\cite{p18_deepseekcoder,p22_starcoder2,p32_codellama,p27_phi3,p45_phi_evolution,p21_qwen2_5coder,p41_qwen_moe}. \textsc{DeepSeek-Coder-V2}, \textsc{StarCoder2}, \textsc{CodeLlama}, \textsc{Phi-3}, and \textsc{Qwen2.5-Coder} achieve high accuracy on isolated function benchmarks but degrade on multi-file repository tasks without explicit context management. MAgHARCM's chunked-translation strategy is designed precisely for the small-model regime: bounded per-fragment context, reverse-topological scheduling, and a multi-stage validation cascade compensate for the small context windows of 4B--7B coding models.

\subsection{Test Translation and Coverage-Guided Test Generation}
\label{sec:related_tests}

Test translation is harder than code translation because test logic depends on the same type system as the source code under test~\cite{p45_translation_bugs}. \textsc{GlueTest}~\cite{p01_gluetest} validates translation through language interoperability. \textsc{Spectra}~\cite{p42_spectra} captures natural-language specifications from source code to inform translation. Coverage-guided test generation~\cite{p20_evosuite,p23_pynguin,p49_codamosa,lemieux2023codamosa} produces additional tests that exercise unvalidated code paths. MAgHARCM's Validator Agent combines translation validation with coverage-guided test generation, emitting additional Rust tests when source coverage is thin and validating them against the source-language equivalents before adding them to $T_t$.
